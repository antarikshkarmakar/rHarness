What it is

Not a chatbot. A harness that finishes.

Most agents talk about the work. rHarness closes the loop on it — with a clear contract, real execution through plugins, and a Finish phase that checks the work actually happened before it stops.

Finish-first by design

The loop's job is completion. It re-enters the cycle with more context until the success criteria are genuinely met — or it tells you honestly that it can't be done yet.

Plugin-based, extensible

Every capability — filesystem, shell, memory, web search, code execution — is a plugin that plugs into specific phases. Add your own and the loop immediately has new hands.

Local-first, open

Runs on your machine with a single command. Bring your own model key, or run in demo mode to see the whole pipeline. Everything is MIT-licensed and inspectable.

How it works

One intent in. Verified work out.

Describe the outcome you want. The harness does the reasoning, calls its plugins, and reports what it shipped.

1

You state the intent

A plain-English task — "write a pitch for this repo", "refactor X and prove it still works". No schema, no ceremony.

2

The loop interrogates & contracts

It clarifies goals, non-goals, assumptions and risks, and writes a success contract it will hold itself to.

3

Plugins do the execution

Reads, writes, runs commands, searches, executes code — each scoped to the phase that needs it, with hard timeouts and sandboxing.

4

Finish verifies — or loops again

The Finish phase checks the contract. If the work isn't done, the loop restarts with everything it learned. When it is, you get the result and the artifacts.

The four phases

Every cycle is the same four moves.

01

Interrogate

Question the task. Pull in context — files, web, memory — and surface what's ambiguous, missing, or at risk before committing.

phases: all · goal: understand
02

Contract

Turn understanding into a commitment: concrete goals, non-goals, assumptions, and a measurable success criteria the loop will be judged by.

produces: contract
03

Execute

Do the work. Plugins act on the world — read, write, run, search, execute — with timeouts, sandboxing, and structured outputs.

produces: artifacts
04

Finish

Verify the contract was actually met. If yes, stop and report. If no, the loop goes back to Interrogate with everything it knows.

produces: verdict
Architecture

A small, honest stack.

TypeScript core on the Bun runtime, a thin web control deck, and a Rust workspace for the performance-critical paths.

Features

Built to be useful, not just demo-able.

🔁 Self-verifying loop

A Finish phase that checks the work before stopping — the difference between "I did it" and "it's done".

🧩 Swappable plugins

Toggle capabilities on/off in the UI. Each plugin declares which phases it can act in.

🛡️ Bounded execution

Hard timeouts, size caps, and path-traversal guards on every plugin that touches the system.

💾 Durable memory

An in-process key/value store (with optional JSON persistence) shared across phases and runs.

🌐 Local web deck

A single-command local UI for chatting, running tasks, managing plugins, and inspecting runs.

🔌 Open by default

MIT-licensed, provider-agnostic, and structured so your own plugins and agents slot in cleanly.
